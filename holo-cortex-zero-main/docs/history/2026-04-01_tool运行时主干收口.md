# 2026-04-01 tool 运行时主干收口

## 目标
- 禁止 Tool handler 再接收任何原始 bot 上下文对象
- 统一由框架把运行时信息收口为显式 runtime 参数与 `tool_host`
- 删除 Tool 主干中的旧上下文兼容与暴露痕迹，避免模型和开发者形成错误心智

## 本次修改
- `holo_cortex_zero/services/tools/registry.py`：删除旧上下文注入兼容，Tool 执行期只保留显式 runtime 参数与 `tool_host`
- `holo_cortex_zero/services/tools/registry.py`：内部运行时包装改为仅服务主干，不再作为 Tool handler 的公开入参语义
- `holo_cortex_zero/services/tools/host/bridge.py`：桥接层删除 raw 上下文回退，统一只依赖 runtime
- `holo_cortex_zero/services/moment/service.py`：删除 `echo` / `vow` 的僵尸上下文参数
- `holo_cortex_zero/services/command_handler.py`：`/exec` 路径把触发现场收口成 runtime binding，不再向 tool 主干传旧上下文型参数
- `holo_cortex_zero/services/tools/chain_executor.py`：Tool 链执行期只传 runtime binding，并同步清理旧文案中的上下文心智
- `docs/guides/tool-integration.md`：更新接入约束，明确 Tool handler 不再接收任何旧上下文型入参

## 影响
- `chat_key` 运行时参数现在明确表示当前锚定的对话窗口（`dialog_chat_key`），不再混用逻辑 `context_id`
- 缺少 `context_id` / `dialog_chat_key` 的 Tool 调用会在执行期硬拒，不再静默回填为另一种窗口标识
- Tool handler 现在只能依赖显式 runtime 参数、`tool_host`、以及 Tool 自身配置
- 旧代码若仍假定 Tool 可以拿到原始 bot 上下文对象，现在会在开发期直接暴露问题，而不会再被框架偷偷兼容
- `weather`、文件发送、托管文件写入等主干能力继续可用，但依赖的是 runtime，而不是原始 bot 上下文对象

  - `weather` 成功完成 Geo -> Weather -> Indices 调用链
  - `tool_host.write_managed_file(...)` 使用 runtime 聊天窗口写入成功
  - `tool_host.send_file(...)` / `runtime.send_text(...)` 仅依赖 runtime 成功走消息主干
