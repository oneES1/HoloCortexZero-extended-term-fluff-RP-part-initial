# 2026-04-01 开发流单命令收口

## 这次做了什么
- 把原来三段式开发流收口成一个主入口：`uv run poe dev`
- 保留现有依赖容器、后端热重载、前端 Vite，不新增开发主应用容器

## 人话版
- 你平时改代码、看效果，就用：`uv run poe dev`
- `uv run poe dev-docs` 和 `uv run poe dev` 的区别只有一个：
  - `dev-docs` 会把后端接口文档也打开
  - 其他行为完全一样
- 所以如果你不是在看接口文档，平时就用 `uv run poe dev`

## 我到底该用哪个命令
- 我想正常开发，前后端都要热更新：`uv run poe dev`
- 我在改接口，想顺手看后端文档页：`uv run poe dev-docs`
- 我只想跑后端：`uv run poe dev-backend`
- 我只想跑前端：`uv run poe dev-frontend`
- 我只想启动开发依赖容器：`uv run poe dev-deps-up`
- 我想停掉开发依赖容器：`uv run poe dev-deps-down`
- 我想看开发依赖容器状态：`uv run poe dev-deps-ps`

## 开发时怎么用
### 第一次启动
1. `cd /path/to/source-root`
2. `cp .env.example .env.dev`
3. `pnpm --dir frontend install --frozen-lockfile`
4. `uv run poe dev`

### 平时改代码
- 改 Python 后端代码：`uv run poe dev` 里会自动热重载
- 改前端代码：`uv run poe dev` 里 Vite 会自动刷新
- 大多数情况下，你不需要自己手动起 Postgres / Qdrant / NapCat，`uv run poe dev` 会先帮你起开发依赖容器

## 我改完代码后，怎么让当前运行版本可用
这里说的是把改动同步到当前 Docker 运行态，不是开发热更新。

### 1. 只改了 Python 后端代码
直接重建主服务容器，不用重装依赖：
- `cd /path/to<CONTAINER_WORKSPACE_DIR>`
- `printf '<SUDO_PASSWORD>\n' | sudo -S docker compose -f docker-compose.yml up -d --force-recreate holo_cortex_zero`

### 2. 改了前端页面或前端静态资源
先重新构建前端，再重建主服务容器：
- `cd /path/to/source-root`
- `pnpm --dir frontend build`
- `cd /path/to<CONTAINER_WORKSPACE_DIR>`
- `printf '<SUDO_PASSWORD>\n' | sudo -S docker compose -f docker-compose.yml up -d --force-recreate holo_cortex_zero`

### 3. 改了依赖、`dockerfile`、锁文件、系统包相关内容
这类改动要重新 build 镜像：
- `cd /path/to<CONTAINER_WORKSPACE_DIR>`
- `printf '<SUDO_PASSWORD>\n' | sudo -S docker compose -f docker-compose.yml up -d --build --force-recreate holo_cortex_zero`
