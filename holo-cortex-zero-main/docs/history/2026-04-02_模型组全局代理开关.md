# 2026-04-02 模型组全局代理开关

## 背景

- 现状是模型调用大量直接读取模型组 `CHAT_PROXY`，各链路分散传入。
- 运行时 HTTP 客户端普遍使用 `trust_env=False`，仅依赖容器环境变量不能统一接管。
- 目标是把代理地址收口到系统设置里的 `DEFAULT_PROXY`，并让每个模型组只保留“是否走全局代理”的开关。

## 本次修改

- `ModelConfigGroup` 新增 `USE_GLOBAL_PROXY` 开关。
- 新增 `holo_cortex_zero/core/proxy_utils.py`，统一解析模型组出站代理。
- `agent`、`auto_memory`、`subconscious`、`ai_reply`、`system_voice`、`image_generation` 全部改为走统一代理解析。
- 模型组前端页面把代理输入主操作替换为“启用全局代理”开关，列表页显示代理策略状态。

## 兼容策略

- 未启用 `USE_GLOBAL_PROXY` 时，继续兼容旧的 `CHAT_PROXY`。
- 启用 `USE_GLOBAL_PROXY` 但 `DEFAULT_PROXY` 为空时，后端打告警日志并退回直连。

## 当前运营配置

- 当前准备把所有 `Uni-*` 模型组打上 `USE_GLOBAL_PROXY=true`。
- 全局代理地址写入系统设置 `DEFAULT_PROXY`，运行态先使用容器可达的 `socks5h://<CONTAINER_SOCKS_PROXY>`。
