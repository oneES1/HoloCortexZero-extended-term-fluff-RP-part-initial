# 模型测速调研总结（2026-02-14）

## 1. 调研范围

- 测试方式：统一使用流式请求（`stream=true`），提示词为“请用中文写一段约80字的自我介绍。”
- 核心指标：
  - **首字延迟（TTFT）**：请求发出到收到首个可见输出的耗时
  - **端到端速度（tok/s）**：`completion_tokens / total_time`
  - **可见文本速度（字/s）**：`可见content字符数 / total_time`
- 说明：不同平台对 `completion_tokens` 统计口径不同，跨平台更建议优先看 **TTFT + 字/s**。

## 3. 关键结论

1. **低延迟优先（首字）**
   - UniAPI 下：`grok-4-fast-non-reasoning`（0.454s）与 `gemini-2.5-flash-lite`（0.681s）表现最好。

2. **GLM-4.7 去思维链可行**
   - 有效参数：`"thinking": {"type": "disabled"}`
   - 其他尝试（如 `reasoning=false` / `reasoning.enabled=false`）要么报错要么无效。

3. **部分模型虽然名字不带 reasoning，但仍需看返回结构**
   - 例如 `deepseek-r1-distill-qwen-32b`、`glm-4.7` 默认都可能只回 reasoning 字段，需按业务判定是否可用。

4. **同一模型在不同平台可用性差异明显**
   - `kimi-k2-0905-preview` 在 UniAPI 当前不可用（503）；
   - `deepseek-r1-distill-llama-70b` 在 DashScope 当前权限不足（403）。

5. **`reasoning_effort` 支持值因模型而异**
   - 不能一刀切使用 `minimal` 或 `none`，需按模型支持矩阵动态配置。

---

## 4. 配置建议（可直接落地）

- 追求低延迟对话：
  - 优先：`grok-4-fast-non-reasoning`、`gemini-2.5-flash-lite`
- 需要 GLM 且不要思维链：
  - 使用：`glm-4.7 + thinking.type=disabled`
- Fox GPT 系列：
  - 先按模型能力选择 `reasoning_effort`（`none`/`minimal`/`low`），避免 400 unsupported 错误
  - 接口优先用 `chat/completions`（当前 `responses` 在该网关被拦）

## 6. 框架侧提速增补（2026-02-15）

> 本节关注“用户发消息 -> 用户看到首条可见回复”这条链路，不仅是模型 TTFT。

### 6.1 已落地改动（按收益优先）

1. **沙盒常驻 Worker（容器内长期 Python 进程）**
   - 在 `warm/hybrid` 策略下，命中会话走 Worker 执行，减少重复冷启动与进程初始化成本。
   - 关键配置：
     - `SANDBOX_PERSISTENT_WORKER_ENABLED=true`
     - `SANDBOX_PERSISTENT_WORKER_CHAT_PREFIXES=["telegram-private_"]`
     - `SANDBOX_PERSISTENT_WORKER_STARTUP_TIMEOUT_SECONDS=8`
     - `SANDBOX_PERSISTENT_WORKER_FALLBACK_TO_EXEC=true`

2. **沙盒热路径减载**
   - `matplotlib` 改为懒加载，避免每次执行都承担全量 import 成本。
   - `api_caller.py` 由“每次覆盖写”改为“内容变化才写入”，减少无效 I/O。

3. **RPC 路径微优化**
   - `AgentCtx` 增加 5 秒短缓存（同容器/同会话复用），减少高频重复构建。
   - `add_memory` 走 fire-and-forget（后台执行），主流程不再等待写入完成。

4. **TG 用户可见流式体感优化**
   - Telegram 启用占位流式编辑，首屏提示统一为：`我在哦...`（含点动画）。

### 6.2 观测到的效果（近期样本）

- 沙盒执行耗时 `exec_time_ms`：**约 3869ms -> 约 1450ms**（降幅约 **62.5%**）。
- 结论：沙盒已从主瓶颈降为次要瓶颈，端到端主要耗时开始集中在“上下文/记忆 + 模型首字”阶段。

### 6.3 当前端到端耗时拆解（消息接收 -> 首条可见）

> 以下为当前链路的经验区间（会随模型、插件、网络抖动变化）：

1. 适配器入站与事件分发：`0.2s ~ 0.8s`
2. 历史渲染 + 提示词注入 + 记忆检索：`1.5s ~ 4.5s`
3. 模型首字（TTFT）：`0.5s ~ 2.5s`（取决于模型/网关）
4. 沙盒执行（已优化后）：`1.2s ~ 2.0s`
5. 回包发送/编辑（含 TG edit）：`0.2s ~ 1.0s`

### 6.4 现阶段最值得继续优化的点

1. **上下文与记忆链路限时化**
   - 对注入器/记忆检索设置硬超时，超时直接降级简版注入，优先保证首条可见回复。

2. **减少重复检索与重复渲染**
   - 对同会话短时间内重复 query 做轻量去重/缓存，避免连续消息重复扫库。

3. **保持“可回退”原则**
   - 所有加速开关保持可配置、可降级，确保在异常场景下稳定性优先。
