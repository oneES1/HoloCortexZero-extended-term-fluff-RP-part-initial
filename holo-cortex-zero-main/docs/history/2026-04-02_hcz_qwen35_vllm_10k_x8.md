# 2026-04-02 hcz 远端 qwen35 vLLM 调整为 10K × 8

## 背景

- 远端工作站 `hcz` 上的 `qwen35-vllm-w4a16.service` 之前长期以 `100000` 上下文、`1` 并发运行。
- 该形态更偏向单条超长链路，不适合当前“短上下文辅助 LLM 池”的新定位。
- 本轮目标是把远端 resident `vLLM` 改成：
  - 默认 `chat` 场景优先
  - 保留 prefix caching
  - 默认上下文上限 `10240`
  - 默认并发 `8`

## 修改点

### 运行态入口

- 远端实际运行脚本：`/path/to/services/qwen35_stack/run/start_vllm_w4a16.sh`
- 本地仓库对应源文件：`scripts/hcz_qwen35/start_vllm_w4a16.sh`

### 默认参数调整

- `QWEN35_VLLM_W4A16_MAX_MODEL_LEN`
  - 从默认 `100000` / `40960` 收敛为 `10240`
- `QWEN35_VLLM_W4A16_MAX_NUM_SEQS`
  - 从默认 `1` 提高到 `8`

### 保持不变

- `--enable-prefix-caching` 保持开启
- `--kv-cache-dtype fp8` 保持不变
- `--gpu-memory-utilization 0.98` 保持不变
- 不碰 FRP / 隧道服务本身，只重启 `qwen35-vllm-w4a16.service`

## 验证结果

- 远端 `systemctl --user status qwen35-vllm-w4a16.service` 显示新进程参数已生效：
  - `--max-model-len 10240`
  - `--max-num-seqs 8`
- 本机通过隧道访问 `http://<LOCAL_OPENAI_COMPAT_HOST>:18081/v1/models`，返回模型 `max_model_len=10240`

## 风险

- 并发提升到 `8` 后，若单请求实际 prompt 长度长期逼近 `10K`，仍可能出现吞吐抖动。
- 当前只调整了 `vLLM` 服务端预算；调用侧是否真正长期稳定在 `<=5K`，还需要后续继续收敛。

## 回滚

- 将 `start_vllm_w4a16.sh` 中默认值改回：
  - `MAX_MODEL_LEN=100000`
  - `MAX_NUM_SEQS=1`
- 然后执行：
  - `systemctl --user restart qwen35-vllm-w4a16.service`

## 备注

- 远端运行脚本已自动备份一份时间戳副本，位于同目录下：`start_vllm_w4a16.sh.bak-<timestamp>`。
