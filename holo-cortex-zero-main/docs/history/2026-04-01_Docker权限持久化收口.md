# 2026-04-01 Docker 权限持久化收口

## 目标
- 修掉运行时权限漂移，避免重建后再次出现 `configs` / `logs` / `postgres_data` 属主错乱
- 保证当前主服务、NapCat、Postgres 在重建后仍可正常启动
- 宿主 `code-server` 继续可编辑运行配置与业务产物目录

## 本次主线调整
- 新增宿主权限初始化脚本：`holo-cortex-zero-main/docker/init_runtime_permissions.sh`
  - 统一修正 `configs`、`logs`、`uploads`、`tool_state`、`system`、`static`、`napcat_data`、`hpc_shared`
  - 强制 `postgres_data` 归 `999:999`
- 新增 app 启动脚本：`holo-cortex-zero-main/scripts/hcz_runtime_entrypoint.sh`
  - 每次启动统一 `umask=0002`
  - 确保主服务业务目录保持 setgid / 组可写
- 新增 postgres 启动脚本：`holo-cortex-zero-main/scripts/hcz_postgres_entrypoint.sh`
  - 每次启动前先修正 `postgres_data` 权限，再交给官方 `docker-entrypoint.sh`
- 新增 NapCat 启动脚本：`holo-cortex-zero-main/scripts/hcz_napcat_entrypoint.sh`
  - 每次启动统一 `umask=0002`
  - 保证 NapCat 数据目录组可写

## Compose / 安装链同步
- 修改文件：
  - `docker-compose.yml`
  - `holo-cortex-zero-main/docker/docker-compose.dev.yml`
  - `holo-cortex-zero-main/docker/install.sh`
  - `holo-cortex-zero-main/docker/install_i18n.sh`
  - `holo-cortex-zero-main/docker/wrtinstall.sh`
  - `holo-cortex-zero-main/docker/.env.example`

  - `HCZ_RUNTIME_UID`
  - `HCZ_RUNTIME_GID`
  - `HCZ_RUNTIME_UMASK`
- `compose up` 链路新增一次性 `hcz_permissions_init` 服务，保证以后重建先修权限再启动业务容器

## 后续去冗余
- 误导性的备用部署模板 `holo-cortex-zero-main/docker/docker-compose.yml` 与 `holo-cortex-zero-main/docker/docker-compose-x-napcat.yml` 已删除
- 当前部署主干只保留根目录 `docker-compose.yml`
- `install.sh`、`install_i18n.sh`、`wrtinstall.sh` 中失效的 `WITH_NAPCAT` / `--with-napcat` 分支已删除，安装链固定走单一部署主干
- 根目录 `docker-compose.yml` 已补回唯一主干所需的 `build` 定义，现有安装脚本的 `build holo_cortex_zero` 再次成立
- 根目录 `docker-compose.yml` 已改为直接写死 `./holo-cortex-zero-main` 与 `dockerfile`，不再依赖 `HCZ_SOURCE_DIR` / `HCZ_DOCKERFILE` 僵尸配置

## 当前运行态策略
- `holo_cortex_zero`：root 启动 + wrapper 收口目录权限
- `hcz_napcat`：`0:1000` + wrapper 收口目录权限
- `hcz_postgres`：官方 entrypoint 前置权限修正，数据目录保持 `999:999`
- `hcz_qdrant`：保持原样，不额外改用户策略

## 验证结果
- WebUI 平台管理员登录接口返回 `200`
- `GET /api/health` 返回 `200`
- 最近运行日志中未再出现新的 `Permission denied`
- 当前宿主关键目录权限：
  - `configs` -> `ubuntu:ubuntu`
  - `logs` -> `ubuntu:ubuntu`
  - `napcat_data` -> `ubuntu:ubuntu`
  - `postgres_data` -> `999:999`
  - `hpc_shared` -> `ubuntu:ubuntu`

## 风险说明
- `holo_cortex_zero` 仍以 root 启动，但权限漂移已由启动 wrapper 和 init service 收口
- PostgreSQL 官方镜像仍由官方 entrypoint 完成最终启动，只是在其前面加了一层权限校正
- 这是为当前现网稳定性做的最小持久化方案，没有引入额外外部依赖镜像
