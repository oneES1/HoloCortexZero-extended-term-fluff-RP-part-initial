# 2026-05-21 Mac Desktop Native Full Plan

## Scope

This log records the Linux-side preparation for moving HCZ into a full native macOS desktop development track.

Linux work in this phase is limited to documentation, handoff packaging, and repository scaffolding. It does not validate macOS-native binaries, dylib loading, app signing, WebView behavior, or NapCat native runtime behavior.

## Security Boundary Split

### Linux Public Server Mode

- WebUI may be exposed beyond the local machine.
- Password-based login must remain available.
- Deployment secrets and administrator password are managed by deployment configuration such as `.env`.
- Existing weak-secret rejection remains valid for server deployments.

### macOS Desktop Mode

- WebUI must bind to loopback only: `127.0.0.1`.
- The user-visible login page should be bypassed in the desktop shell.
- The authentication trunk should not be deleted. Desktop mode should use a local session or local token injected by the desktop runtime.
- If desktop-local authentication is enabled while the backend binds to a non-loopback address, startup should fail.

Target user experience:

```text
Open HCZ.app
-> local runtime starts backend services
-> WebView opens http://127.0.0.1:20261
-> user enters WebUI directly
```

## Proxy Boundary

The WebUI itself talks to the local backend and does not need an outbound proxy.

Outbound API traffic is generated by the HCZ backend process, so desktop proxy configuration must be injected into the backend process environment by the desktop runtime manager. Finder-launched macOS apps do not reliably inherit shell `export` values.

First desktop proxy modes:

- `off`
- `manual`

Manual Clash-style template:

```env
HTTP_PROXY=http://127.0.0.1:7890
HTTPS_PROXY=http://127.0.0.1:7890
ALL_PROXY=socks5h://127.0.0.1:7891
NO_PROXY=127.0.0.1,localhost,::1
```

Later desktop proxy modes can include `system`, where the desktop shell reads macOS system proxy settings and converts them to process environment variables for HCZ.

## Native Runtime Port Contract

The first full native macOS target uses local loopback services:

| Service | Host | Port | Purpose |
| --- | --- | ---: | --- |
| HCZ backend/WebUI | `127.0.0.1` | `20261` | Main API and WebUI |
| PostgreSQL | `127.0.0.1` | `55432` | Relational state |
| Qdrant | `127.0.0.1` | `56333` | Vector state |
| NapCat | `127.0.0.1` | `56535` | OneBot/NapCat local runtime |

NapCat must not be exposed to the public network. The preferred user path remains through HCZ WebUI reverse proxy routes, or explicit local-loopback access during debugging.

## Required Upstream Generalization Candidates

These are candidates only; this preparation phase does not implement them.

1. Add an explicit run mode, for example `HCZ_RUN_MODE=server|desktop`.
2. Add an explicit auth mode, for example `HCZ_WEB_AUTH_MODE=password|desktop_local`.
3. Ensure `desktop_local` auth refuses non-loopback backend binds.
4. Keep service addresses configurable through existing config/env surfaces.
5. Abstract Docker container status/control into a runtime provider so local-process desktop runtime does not inherit Docker-only assumptions.
6. Keep proxy handling in the common network/config layer. The desktop app writes or injects config; LLM provider code should not fork per platform.

## Linux Preparation Non-Goals

- Do not build Docker images.
- Do not restart production containers.
- Do not read full logs.
- Do not test macOS dylib loading on Linux.
- Do not validate Qdrant, PostgreSQL, or NapCat macOS binaries on Linux.
- Do not modify the production Docker entry path.
- Do not add desktop-specific protocol branches to LLM providers.

## First macOS Verification Order

Before building an `.app`, the Mac must run the native process chain directly:

1. Verify OS and CPU architecture.
2. Verify Python 3.11 or 3.12.
3. Verify Node and pnpm for frontend build.
4. Verify `ffmpeg` and `ffprobe`.
5. Start PostgreSQL on `127.0.0.1:55432`.
6. Start Qdrant on `127.0.0.1:56333`.
7. Start NapCat on `127.0.0.1:56535`.
8. Start HCZ backend with desktop env.
9. Check `http://127.0.0.1:20261/api/health`.
10. Open `http://127.0.0.1:20261` in a normal browser.
11. Only after the browser path works, wrap it in Tauri or Electron.
