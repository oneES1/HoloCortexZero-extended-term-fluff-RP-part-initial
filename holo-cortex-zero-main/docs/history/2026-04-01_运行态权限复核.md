# 2026-04-01 运行态权限复核

## 目标
- 复核当前是否还存在“权限问题导致业务错误”的运行态风险
- 区分“已修复的业务阻断”与“仅影响宿主人工维护的权限摩擦”

## 本次检查范围
- `holo_cortex_zero`
- `hcz_postgres`
- `hcz_qdrant`
- `hcz_napcat`
- 宿主运行目录 `/path/to/runtime-data`
- 仓库共享目录 `/path/to<CONTAINER_WORKSPACE_DIR>/hpc_shared`（唯一共享文件主干，`HCZ_DATA_DIR` 下不再保留同名影子目录）

## 当前结论
- 当前**没有发现仍在触发业务错误的权限问题**
- 已验证：
  - WebUI 平台管理员登录接口返回 `200`
  - WebUI 受保护接口鉴权返回 `200`
  - Postgres 查询 `select 1` 正常
  - `holo_cortex_zero`、`hcz_napcat`、`hcz_qdrant`、`hcz_postgres` 关键挂载目录均可读写
- 最近 3 分钟容器日志中未再出现新的 `Permission denied`

## 已确认恢复正常的关键点
- `postgres_data` 已恢复为 Postgres 运行用户 `999:999` 可读写
- 运行配置目录 `configs/` 已恢复为 `ubuntu:ubuntu`，code-server 可编辑
- WebUI 静态资源已切到当前新版构建

## 仍需注意的非阻断风险
- `holo_cortex_zero` 与 `hcz_napcat` 当前仍以 `root` 运行
- 因此以下业务产物会继续在宿主机上生成 `root:root` 文件：
  - `/path/to/runtime-data/logs`
  - `/path/to/runtime-data/uploads`
  - `/path/to/runtime-data/tool_state`
- 这**目前不构成运行时业务错误**，但会带来：
  - 宿主人工清理/编辑不便
  - code-server 若直接改这些运行产物，可能再次遇到权限问题

## 建议
- 若后续要彻底消除权限漂移，建议单独收口容器运行用户策略
- 在此之前，不要再对 `postgres_data` 执行宿主侧 `root:root` 回写或批量 `chmod/chown`
