# 2026-04-01 seek 工具参数收口

## 背景

`seek` 作为普通公开 Tool，原先把 `max_results`、`search_depth`、`topic`、`time_range`、`include_answer` 一并暴露给模型。
这会让模型在每次调用时自行决定搜索深度、主题与返回条数，和面板配置产生双入口。

本次按“删除优先、主干收口”的原则处理：

- 只保留模型需要表达的业务意图：`query`
- 其余行为全部回收到 Tool 面板配置
- 不保留并行参数通道，不做 provider 特化兼容

## 修改点

- 收口 `tool_runtime/tools/seek.py` 的 `PARAMETERS`，只公开 `query`
- 删除 `seek(...)` handler 的调用期覆盖参数：
  - `max_results`
  - `search_depth`
  - `topic`
  - `time_range`
  - `include_answer`
- handler 统一只从 `SeekConfig` 读取：
  - `RESULT_COUNT`
  - `SEARCH_DEPTH`
  - `TOPIC`
  - `TIME_RANGE`
  - `INCLUDE_ANSWER`

## 影响

- 模型侧 Tool schema 更稳定，不再被诱导生成搜索策略类参数
- 面板配置成为唯一控制入口，行为更可调试、可持久化
- 仓库内未发现其他直接调用 `seek(...)` 传这些参数的代码路径，因此本次删除影响面可控

## 验证

使用隔离脚本直接调用 `seek` handler，并真实访问 Tavily：

- 代理：`HTTP_PROXY=http://<LOCAL_HTTP_PROXY>`
- 产物：`/tmp/hcz_seek_isolated_check/summary.json`
- 期望：请求成功、返回 `ToolOutcome(text)`、日志包含 `seek tool start` 与 `seek tool success`
